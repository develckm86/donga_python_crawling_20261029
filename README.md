# 웹 크롤링으로 데이터 모으고, AI로 다듬고, 매일 자동으로 돌리기

웹사이트의 음악 순위를 파이썬으로 모으고(크롤링), Claude AI로 인스타그램 카드뉴스 문구를 만들고, 엑셀로 저장한 뒤, 매일 아침 자동으로 실행되게 만듭니다.

```
웹페이지 ──수집──▶ 순위 표 ──AI 변환──▶ 카드뉴스 문구 ──저장──▶ 엑셀 ──예약──▶ 매일 자동 실행
 (requests,          (pandas)    (Claude API)                 (pandas)      (작업 스케줄러)
  BeautifulSoup)
```

## 이 수업을 마치면

- 웹페이지의 HTML을 받아서 원하는 정보만 골라낼 수 있습니다. (requests, BeautifulSoup)
- 자바스크립트로 그려지는 페이지도 브라우저를 조종해서 모을 수 있습니다. (Playwright)
- 모은 데이터를 AI에게 보내 글을 만들게 할 수 있습니다. (Claude API)
- 결과를 엑셀로 저장하고, 매일 정해진 시각에 자동으로 돌릴 수 있습니다. (작업 스케줄러)

## t01. 아이차트 순위 → 카드뉴스 → 엑셀

**목표**: 크롤링의 기본 흐름 **수집 → 추출 → 변환 → 저장**을 한 번에 경험합니다.

| 단계 | 코드에서 하는 일 | 쓰는 도구 |
|---|---|---|
| 1. 수집 | 주소로 요청을 보내 HTML 글자를 받음 | `requests.get()` |
| 2. 추출 | HTML에서 순위·곡명·가수만 골라 표로 만듦 | `BeautifulSoup`, `select()` |
| 3. 변환 | 표를 Claude에게 보내 카드뉴스 문구(JSON)를 받음 | `anthropic` |
| 4~5. 저장 | 엑셀 파일에 시트 두 개(순위, 카드뉴스)로 저장 | `pandas` |

**핵심 개념**

- **선택자(selector)**: HTML에서 원하는 태그를 찾는 주소입니다. 브라우저에서 **F12 → 요소 선택(왼쪽 위 화살표)** 으로 순위 한 줄을 눌러 구조를 확인합니다.
  ```python
  area.select('a[href*="/song/"]')   # href에 "/song/"이 들어간 a 태그 = 곡 하나
  a.select_one("h3").get_text()       # 그 안의 h3 = 곡명
  ```
- **User-Agent**: 요청을 보낼 때 "저는 브라우저입니다"라고 알려 주는 머리말입니다. 없으면 막는 사이트가 있습니다.
- **JSON으로 답하게 하기**: AI의 답을 코드에서 바로 쓰려면 형식을 정해 줘야 합니다. 프롬프트에 `{"제목": ..., "카드": [...], "해시태그": [...]}` 모양을 보여 주고 "JSON으로만 답할 것"이라고 씁니다.

**결과 확인**: `output\ichart_2026-10-29.xlsx`를 열어 `순위`, `카드뉴스` 두 시트를 확인합니다. 카드뉴스 시트 맨 아래에는 "출처: 아이차트(ichart.kr)"와 "AI 생성 초안 · 검수 후 게시"가 들어갑니다.

## t03. 동적 페이지: 아이차트 레코드 (Playwright)

**목표**: requests로는 안 보이는 데이터를 진짜 브라우저로 모읍니다.

**왜 requests로는 안 될까?** 노트북 ① 셀을 실행하면 상태 코드는 200(성공)인데 곡이 **0개**입니다.

| 확인 방법 | 보이는 것 | 곡 목록 |
|---|---|---|
| **Ctrl+U** (페이지 소스) | 서버가 처음 보낸 HTML = requests가 받는 것 | 없음 |
| **F12 → Elements** | 자바스크립트가 실행된 뒤의 화면 | 있음 |

이 페이지는 자바스크립트가 나중에 목록을 그립니다. requests는 자바스크립트를 실행하지 못하므로, 브라우저를 직접 조종하는 **Playwright**를 씁니다.

**가상 스크롤**: 이 목록은 100곡이 넘지만, 화면 근처 20~30줄만 HTML에 있습니다. 스크롤하면 위쪽 줄은 지워지고 아래쪽 줄이 새로 그려집니다. 그래서 **조금씩 내리면서 그때그때 읽어 모읍니다.**

```
반복 (최대 100번)
  ├─ 지금 화면의 곡을 읽어 딕셔너리에 담기 (링크가 키 → 같은 곡은 한 번만)
  ├─ 새 곡이 3번 연속 없으면 → 맨 아래 도착, 멈춤
  └─ 600px 아래로 스크롤, 0.5초 기다리기
```

> 노트북에서는 `async_playwright` + `await`를, `.py` 파일에서는 `sync_playwright`를 씁니다. 노트북 안에서 `sync_playwright`를 쓰면 오류가 납니다.

## 자동화. 매일 아침 자동으로 실행하기

**목표**: 내가 PC 앞에 없어도 정해진 시각에 크롤링이 저절로 돌아가게 만듭니다.

### 누가 무엇을 하나요?

```
작업 스케줄러 (Windows에 들어 있는 "알람 시계" 프로그램)
   │  매일 09:00이 되면
   ▼
run_daily.bat (실행 순서를 적어 둔 "심부름 쪽지")
   │  쪽지에 적힌 대로
   ▼
.venv\Scripts\python.exe t01_ichart_demo.py (실제 크롤링)
   ├─▶ 결과 엑셀: output\ichart_날짜.xlsx
   └─▶ print 출력·오류: logs\run_bat.log 에 이어 쓰기
```

작업 스케줄러는 파이썬을 모릅니다. 그래서 "어느 폴더에서, 어떤 파이썬으로, 어떤 파일을 실행하고, 출력은 어디에 적을지"를 `.bat` 파일에 적어 두고, 작업 스케줄러는 그 `.bat` 파일만 실행합니다.

### run_daily.bat 한 줄씩 읽기

`.bat`(배치 파일)은 명령 프롬프트(cmd)에 칠 명령을 차례로 적어 둔 파일입니다. `rem`으로 시작하는 줄은 설명(주석)이라 실행되지 않습니다.

| 줄 | 뜻 |
|---|---|
| `@echo off` | 실행하는 명령을 화면에 하나하나 보여 주지 않기 |
| `chcp 65001 > nul` | 글자 방식을 UTF-8로 바꾸기 → 한글이 깨지지 않음 (`> nul` = 결과 메시지는 버리기) |
| `cd /d "%~dp0"` | **이 .bat 파일이 있는 폴더로 이동**. `%~dp0` = 이 파일의 폴더 경로, `/d` = C:, D: 같은 드라이브도 바꿈 |
| `set SCRIPT=t01_ichart_demo.py` | 실행할 파이썬 파일 이름을 `SCRIPT`라는 이름에 담기 (`%SCRIPT%`로 꺼내 씀) |
| `set PYTHONUTF8=1` | 파이썬이 한글을 UTF-8로 출력하게 하기 → 로그 파일 한글이 안 깨짐 |
| `if not exist logs mkdir logs` | `logs` 폴더가 없으면 만들기 |
| `echo ===== %date% %time% 시작 ===== >> logs\run_bat.log` | 로그 파일에 "언제 시작했는지" 한 줄 적기 |
| `".venv\Scripts\python.exe" %SCRIPT% >> logs\run_bat.log 2>&1` | **가상환경의 파이썬으로 실행**하고 출력을 로그 파일에 적기 |
| `set RC=%errorlevel%` | 방금 끝난 파이썬의 종료 코드(0 = 성공, 1 = 실패)를 `RC`에 담기 |
| `echo ===== 끝 (결과 %RC%) ===== >> logs\run_bat.log` | 로그 파일에 결과 한 줄 적기 |
| `exit /b %RC%` | 같은 종료 코드를 작업 스케줄러에 알려 주기 → "마지막 실행 결과"에 표시됨 |

**`>>`와 `2>&1`**

| 기호 | 뜻 |
|---|---|
| `>` | 화면 대신 파일에 쓰기 (파일이 있으면 **덮어씀**) |
| `>>` | 화면 대신 파일 **끝에 이어 쓰기** → 매일 기록이 쌓임 |
| `2>&1` | 오류 메시지(2번 통로)도 일반 출력(1번 통로)과 같은 곳에 쓰기 |

**왜 `cd /d "%~dp0"`가 꼭 필요한가요?**
작업 스케줄러는 `.bat`을 `C:\Windows\System32` 같은 엉뚱한 폴더에서 실행합니다. 이 줄이 없으면 `.venv`와 `t01_ichart_demo.py`를 찾지 못합니다.

**왜 그냥 `python`이 아니라 `.venv\Scripts\python.exe`인가요?**
작업 스케줄러는 `activate`를 해 주지 않습니다. 그냥 `python`이라고 쓰면 라이브러리가 설치되지 않은 다른 파이썬이 실행되어 `ModuleNotFoundError`가 납니다.

### ② 예약 등록하기

**준비: run_daily.bat의 전체 경로 복사하기**

탐색기에서 `run_daily.bat`을 마우스 오른쪽 클릭 → **경로로 복사** (단축키 `Ctrl+Shift+C`).
`"C:\Users\내이름\Downloads\crawlday_code\run_daily.bat"`처럼 따옴표까지 함께 복사됩니다.

> 폴더 경로에 **띄어쓰기가 없는 곳**에 두는 것이 안전합니다. (예: `C:\crawl\`)

**방법 A. 명령으로 등록** (PowerShell이나 cmd에서)

> `schtasks`는 Windows에 기본으로 들어 있는 프로그램(`C:\Windows\System32\schtasks.exe`)이라 따로 설치할 필요가 없습니다. 작업 스케줄러 화면과 같은 예약 목록을 쓰므로, 명령으로 등록한 예약도 화면에서 보입니다.

```
schtasks /create /tn "ichart_daily" /tr "C:\경로\run_daily.bat" /sc daily /st 09:00
```

`SUCCESS: The scheduled task "ichart_daily" has successfully been created.` (또는 "성공: 예약된 작업…") 이 나오면 등록 완료입니다.

| 옵션 | 뜻 | 이 예제에서 |
|---|---|---|
| `schtasks` | 작업 스케줄러를 명령으로 다루는 프로그램 | |
| `/create` | 새 예약 **만들기** | |
| `/tn` | **T**ask **N**ame, 예약 이름 (내가 정함, 나중에 실행·삭제할 때 이 이름을 씀) | `"ichart_daily"` |
| `/tr` | **T**ask **R**un, 실행할 파일의 전체 경로 | `"C:\...\run_daily.bat"` |
| `/sc` | **SC**hedule, 반복 주기 | `daily` = 매일 |
| `/st` | **S**tart **T**ime, 시작 시각 (24시간제 `HH:MM`) | `09:00` |
| `/f` | (선택) 같은 이름이 있으면 묻지 않고 **덮어쓰기** | |

**반복 주기 바꾸기 (`/sc` 예시)**

| 하고 싶은 것 | 명령에서 바꿀 부분 |
|---|---|
| 매일 오전 9시 | `/sc daily /st 09:00` |
| 매주 월·수·금 오후 6시 | `/sc weekly /d MON,WED,FRI /st 18:00` |
| 매시간 | `/sc hourly` |
| 5분마다 (수업 중 확인용) | `/sc minute /mo 5` (`/mo` = 몇 단위마다) |
| 오늘 한 번만 오후 2시 30분 | `/sc once /st 14:30` |

**방법 B. 마우스로 등록**

1. 시작 메뉴에서 **작업 스케줄러** 검색 → 실행
2. 오른쪽 **기본 작업 만들기...** 클릭
3. 이름: `ichart_daily` → 다음
4. 트리거: **매일** → 다음 → 시작 시각 `오전 9:00`, 간격 `1`일 → 다음
5. 동작: **프로그램 시작** → 다음
6. 프로그램/스크립트: **찾아보기**로 `run_daily.bat` 선택 → 다음
7. 마침
8. 왼쪽 **작업 스케줄러 라이브러리**를 누르면 목록에 `ichart_daily`가 보입니다.

```
schtasks /run /tn "ichart_daily"
```

몇 초 뒤 다음 세 가지를 확인합니다.

1. `logs\run_bat.log` 맨 아래에 새 `시작`~`끝 (결과 0)` 기록이 생겼는지
2. `output\` 폴더에 오늘 날짜 엑셀이 생겼는지
3. 예약 상태 확인:
   ```
   schtasks /query /tn "ichart_daily" /v /fo list
   ```
   `/query` = 조회, `/v` = 자세히, `/fo list` = 한 줄에 한 항목씩 보기.
   **마지막 실행 시간**, **마지막 결과**, **다음 실행 시간**을 봅니다.

**마지막 결과 숫자 읽기** (마우스로 볼 때는 목록의 "마지막 실행 결과" 칸)

| 값 | 뜻 |
|---|---|
| `0` 또는 `0x0` | 성공 |
| `1` 또는 `0x1` | 파이썬에서 오류 → `logs\run_bat.log` 확인 |
| `0x41301` | 지금 실행 중 |
| `0x41303` | 아직 한 번도 실행 안 됨 |

### ④ 바꾸기와 지우기

```
schtasks /change /tn "ichart_daily" /st 10:00   ← 시각만 10시로 바꾸기
schtasks /delete /tn "ichart_daily" /f          ← 예약 지우기 (/f = "정말 지울까요?" 묻지 않기)
```

> **수업이 끝나면 꼭 지웁니다.** 지우지 않으면 매일 9시에 Claude API가 호출되어 키 사용량이 계속 나갑니다.

### 주의할 점

- **PC가 꺼져 있거나 절전 상태면 실행되지 않습니다.** 그 시각에 PC가 켜져 있어야 합니다.
- **노트북은 배터리일 때 실행되지 않을 수 있습니다.** 작업 스케줄러에서 `ichart_daily` 더블클릭 → **조건** 탭 → "컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작" 체크 해제.
- **로그인한 상태에서만 실행됩니다.** (기본 설정) 수업 실습에는 이대로 충분합니다.
- **내 파일로 바꾸려면** `run_daily.bat`에서 `set SCRIPT=t01_ichart_demo.py` 한 줄만 고칩니다. 예약은 그대로 두면 됩니다.
- **폴더를 옮기면** 예약에 적힌 경로(`/tr`)가 틀려집니다. 지우고 새 경로로 다시 등록합니다.
- `run_daily.bat`을 고쳐 저장할 때는 인코딩 **UTF-8**, 줄 끝 **CRLF(Windows)** 를 유지합니다. VS Code 오른쪽 아래 상태 표시줄에서 확인할 수 있습니다. 줄 끝이 LF로 바뀌면 한글 주석이 명령으로 잘못 읽혀 실행이 깨집니다.

## 자주 나는 오류

| 오류 메시지 / 증상 | 원인 | 해결 |
|---|---|---|
| `ModuleNotFoundError: No module named ...` | 라이브러리가 없거나 `.venv`가 아닌 파이썬으로 실행 | `.venv\Scripts\python.exe`로 실행, 또는 `pip install -r requirements.txt` |
| `Could not resolve authentication method` | API 키를 못 읽음 | `.env` 파일이 이 폴더에 있는지, `ANTHROPIC_API_KEY=` 뒤에 키가 있는지 확인 |
| `AttributeError: 'NoneType' object has no attribute 'get_text'` | 선택자로 태그를 못 찾음 (사이트 구조가 바뀜) | F12로 다시 구조를 보고 선택자 수정 |
| `KeyError: '순위'` | 곡을 하나도 못 모아 표가 비었음 | 위와 같음, 선택자 확인 |
| `json.decoder.JSONDecodeError` | AI가 JSON이 아닌 형식으로 답함 | 다시 실행하거나, 프롬프트에 형식을 더 분명히 적기 |
| Playwright `TimeoutError` | 15초 안에 목록이 안 나타남 | 인터넷 연결, 주소, 선택자 확인 |
| `run_daily.bat` 실행 시 `'작업' is not recognized...` | `.bat` 줄 끝이 LF로 바뀜 | VS Code에서 줄 끝을 CRLF로 바꿔 저장 |
| `schtasks /run` 또는 `/delete` 시 `ERROR: The system cannot find the file specified` | 예약 이름(`/tn`)이 틀림 | `schtasks /query /tn "ichart_daily"`로 이름 확인 |
| 예약 시각이 지났는데 로그에 기록이 없음 | 경로(`/tr`)가 틀림, PC 절전, 배터리 조건 | `schtasks /query ... /v /fo list`로 "마지막 결과"와 "실행할 작업" 경로 확인 |
| 마지막 결과가 `0x1` | `.bat`은 실행됐지만 파이썬에서 오류 | `logs\run_bat.log` 맨 아래 오류 메시지 확인 |
